# 18. RocketMQ 消息队列

> 本教程基于 **Apache RocketMQ 5.3.0 + Spring Cloud Alibaba 2025.1.0.0**
> 难度：⭐⭐⭐⭐ | 预计时间：90 分钟

## 一、为什么需要消息队列？

同步调用的痛点：

| 问题 | 场景 | 后果 |
|------|------|------|
| **耦合** | A → B → C 链式调用 | B 不可用导致 A 失败 |
| **性能** | 下单要调用 5 个服务 | 总耗时 = 5 个服务之和 |
| **流量冲击** | 秒杀 10w QPS | 数据库被打垮 |
| **扩展性** | 新增下游需改主流程 | 上线周期长 |

**RocketMQ 解法**：

```
订单服务 ─发─> RocketMQ ──收──> 库存服务
                       ──收──> 支付服务
                       ──收──> 通知服务
                       ──收──> 搜索服务
```

**核心优势**：
- **解耦**：服务间通过消息通信，新增订阅方无需修改上游
- **异步**：下单后立即返回，库存扣减等逻辑异步执行
- **削峰**：10w QPS 写入 MQ，消费者按能力消费
- **可靠**：消息持久化、多副本、消费 ACK 机制

## 二、RocketMQ 核心概念

```
┌──────────────────────────────────────────┐
│  NameServer（注册中心，集群部署）         │
│  - 管理 Broker 的注册信息                  │
│  - 轻量级（无状态）                        │
└──────────────────────────────────────────┘
                    ▲ ▲ ▲
                    │ │ │
┌──────────────────────────────────────────┐
│  Broker（消息存储与转发）                  │
│  - Master + Slave 集群                   │
│  - 消息持久化到 CommitLog                  │
└──────────────────────────────────────────┘
                    ▲
                    │
┌──────────────────────────────────────────┐
│  Producer / Consumer / Dashboard         │
└──────────────────────────────────────────┘
```

| 概念 | 解释 |
|------|------|
| **Topic** | 消息主题（订单事件、用户通知） |
| **Tag** | Topic 下的子分类（welcome/orderCreated/orderPaid） |
| **MessageQueue** | Topic 的物理分片，分布在不同 Broker |
| **Producer Group** | 同一类生产者的集合 |
| **Consumer Group** | 同一类消费者的集合，集群消费模式下负载均衡 |
| **Broker** | 消息存储节点（Master 处理读写，Slave 同步备份） |
| **NameServer** | 路由注册中心（类似 Eureka） |

## 三、Docker Compose 一键部署

### 3.1 Broker 配置

`docker/rocketmq/broker.conf`：

```properties
brokerClusterName = DefaultCluster
brokerName = broker-a
brokerId = 0
brokerIP1 = rocketmq-broker          # 关键：Docker 内部用服务名
namesrvAddr = rocketmq-nameserver:9876
defaultTopicQueueNums = 4
autoCreateTopicEnable = true
autoCreateSubscriptionGroup = true
listenPort = 10911
brokerRole = ASYNC_MASTER             # 同步双写 / 异步主从
flushDiskType = ASYNC_FLUSH           # 同步刷盘 / 异步刷盘
```

**重要：`brokerIP1` 必须显式声明**！否则 Java 应用（宿主机）连接 Broker 时会用错误的 IP，导致连接失败。

### 3.2 docker-compose.yml

```yaml
rocketmq-nameserver:
  image: apache/rocketmq:5.3.0
  container_name: rocketmq-nameserver
  command: ./mqnamesrv
  ports:
    - "9876:9876"
  environment:
    - JAVA_OPT_EXT=-Xms256m -Xmx256m
  volumes:
    - rocketmq-ns-logs:/home/rocketmq/logs

rocketmq-broker:
  image: apache/rocketmq:5.3.0
  container_name: rocketmq-broker
  command: ./mqbroker -n rocketmq-nameserver:9876 -c /home/rocketmq/rocketmq-5.3.0/conf/broker.conf
  depends_on:
    rocketmq-nameserver:
      condition: service_started
  ports:
    - "10909:10909"
    - "10911:10911"
    - "10912:10912"
  environment:
    - JAVA_OPT_EXT=-Xms512m -Xmx512m
  volumes:
    - rocketmq-broker-store:/home/rocketmq/store
    - rocketmq-broker-logs:/home/rocketmq/logs
    - ./docker/rocketmq/broker.conf:/home/rocketmq/rocketmq-5.3.0/conf/broker.conf:ro

rocketmq-dashboard:
  image: apacherocketmq/rocketmq-dashboard:latest
  container_name: rocketmq-dashboard
  depends_on:
    rocketmq-nameserver:
      condition: service_started
  environment:
    - JAVA_OPTS=-Xmx256m
  ports:
    - "8180:8080"   # 8180 避免与 SkyWalking UI 8080 冲突
```

启动：

```bash
docker-compose up -d rocketmq-nameserver rocketmq-broker rocketmq-dashboard
```

访问 Dashboard：`http://localhost:8180`

## 五、四类典型消息实战

### 5.1 普通消息（同步发送）

**场景**：用户注册成功后异步发欢迎通知。

**Producer**：

```java
public SendResult sendWelcomeMessage(Long userId, String userName) {
    String payload = String.format("{\"userId\":%d,\"userName\":\"%s\"}", userId, userName);
    Message<String> message = MessageBuilder.withPayload(payload)
            .setHeader(RocketMQHeaders.KEYS, UUID.randomUUID().toString())
            .build();
    // destination 格式：topic:tag
    SendResult result = rocketMQTemplate.syncSend(
        userNotifyTopic + ":" + welcomeTag, message);
    return result;
}
```

**Consumer**：

```java
@RocketMQMessageListener(
    topic = "${rocketmq.topic.user-notify}",
    selectorExpression = "welcome",         // 只接收 welcome tag
    consumerGroup = "rocketmq-welcome-consumer"
)
public class WelcomeConsumer implements RocketMQListener<String> {
    @Override
    public void onMessage(String body) {
        log.info("收到欢迎消息: {}", body);
        // 发送欢迎邮件
    }
}
```

**发送与接收模式**：

| 模式 | 方法 | 特点 |
|------|------|------|
| 同步 | `syncSend` | 阻塞等待 Broker 响应，3s 超时 |
| 异步 | `asyncSend` | 发送后立即返回，Broker 响应回调 |
| 单向 | `sendOneWay` | 只发不收，最快（用于日志收集） |

### 5.2 顺序消息

**场景**：同一用户的订单状态必须按创建→支付→完成顺序处理，不能乱。

**核心**：通过 `hashKey`（如 userId）将同一业务的消息路由到固定 MessageQueue，单 Queue 内严格有序。

```java
public SendResult sendOrderedMessage(Long userId, String content) {
    Message<String> message = MessageBuilder.withPayload(content)
            .setHeader(RocketMQHeaders.KEYS, String.valueOf(userId))
            .build();
    // 第 3 个参数 hashKey 决定消息进入哪个 Queue
    return rocketMQTemplate.syncSendOrderly(
        userNotifyTopic, message, String.valueOf(userId));
}
```

**顺序消费的三个铁律**：
1. **Producer 有序发送**：用同一 hashKey 路由
2. **Consumer 单线程串行消费**：`consumeMode = ORDERLY`
3. **最大努力顺序**：Broker 故障重试时可能短暂乱序（业务可接受）

### 5.3 延迟消息

**场景**：用户注册 30 分钟未登录 → 发提醒短信。

```java
public SendResult sendDelayedMessage(Long userId, String content, int delayLevel) {
    Message<String> message = MessageBuilder.withPayload(content).build();
    // 第 4 个参数为延迟级别
    return rocketMQTemplate.syncSend(userNotifyTopic, message, 3000, delayLevel);
}
```

**RocketMQ 延迟级别表**：

| 级别 | 时间 | 级别 | 时间 |
|------|------|------|------|
| 1 | 1s | 10 | 5m |
| 2 | 5s | 11 | 6m |
| 3 | 10s | 12 | 7m |
| 4 | 30s | 13 | 8m |
| 5 | 1m | 14 | 9m |
| 6 | 2m | 15 | 10m |
| 7 | 3m | 16 | 20m |
| 8 | 4m | 17 | 30m |
| 9 | 5m | 18 | 1h |

> **注**：RocketMQ 5.x 已支持任意延迟时间（Broker 配置 `timerWheelEnable=true`），不再受 18 级限制。

### 5.4 事务消息

**场景**：下单成功 → 扣库存 + 扣余额，要么全成功要么全失败。

**两阶段流程**：

```
Producer                Broker             Consumer
   │  1.发送half消息      │                  │
   ├──────────────────> │  消息不可见        │
   │  2.执行本地事务      │                  │
   ├──> 扣库存            │                  │
   │  3.提交/回滚         │                  │
   ├──────────────────> │  消息可见          │
   │                     ├─────────────────> │
   │                     │                  │ 4.消费消息
```

```java
// 1. 发送 half 消息
Message msg = MessageBuilder.withPayload("orderData").build;
rocketMQTemplate.sendMessageInTransaction(
    "order-tx-topic", msg, orderId);

// 2. 实现本地事务监听器
@RocketMQTransactionListener
public class OrderTxListener implements RocketMQLocalTransactionListener {
    
    @Override
    public RocketMQLocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        try {
            // 真正执行本地事务（扣库存）
            inventoryService.deduct((Long) arg);
            return RocketMQLocalTransactionState.COMMIT;
        } catch (Exception e) {
            return RocketMQLocalTransactionState.ROLLBACK;
        }
    }
    
    @Override
    public RocketMQLocalTransactionState checkLocalTransaction(Message msg) {
        // Broker 反查本地事务状态
        return inventoryService.isDeducted(msg.getKeys()) 
            ? COMMIT : ROLLBACK;
    }
}
```

## 六、消费模式

### 6.1 集群消费（默认）

```java
@RocketMQMessageListener(
    consumerGroup = "user-notify-cluster",
    messageModel = MessageModel.CLUSTERING  // 默认
)
```

- **特点**：同一 Consumer Group 内消息只被一个实例消费
- **用途**：负载均衡（水平扩展消费者提高吞吐）

### 6.2 广播消费

```java
@RocketMQMessageListener(
    consumerGroup = "user-notify-broadcast",
    messageModel = MessageModel.BROADCASTING
)
```

- **特点**：所有 Consumer 实例都消费每条消息
- **用途**：本地缓存刷新、配置同步

## 七、消费可靠性

### 7.1 三种 ACK 状态

| 状态 | 含义 | 触发 |
|------|------|------|
| `SUCCESS` | 处理成功 | 业务正常返回 |
| `RECONSUME_LATER` | 稍后重试 | 业务抛异常 |
| 超过最大重试次数 | 进入死信队列 | RocketMQ 自动 |

### 7.2 死信队列

```java
@RocketMQMessageListener(
    topic = "%DLQ%user-notify-topic",  // 死信 Topic 格式
    consumerGroup = "dlq-handler"
)
public class DeadLetterConsumer implements RocketMQListener<String> {
    @Override
    public void onMessage(String body) {
        log.error("死信消息，需人工处理: {}", body);
        // 告警 / 落库 / 人工补偿
    }
}
```

## 八、Spring Cloud Stream 函数式编程（可选）

    return user -> MessageBuilder.withPayload(user)
            .setHeader("type", "user")

@Bean

    return user -> log.info("SCStream 收到: {}", user);

## 十、生产最佳实践

| 维度 | 建议 |
|------|------|
| **Topic 命名** | 业务域_子域_用途（如 `order_event_topic`） |
| **Tag 数量** | 一个 Topic 6-7 个 Tag 以内，避免过多 |
| **Message Size** | 不超过 4MB（默认 `maxMessageSize`） |
| **批量发送** | `syncSend(List)` 提升吞吐，但单批 ≤ 4MB |
| **幂等消费** | 消费端必须用唯一 keys 做去重 |
| **监控** | 消费堆积告警、消费 RT、失败率 |
| **Broker 配置** | 生产环境 SYNC_MASTER + SYNC_FLUSH（强一致） |

## 十一、常见问题

**Q1：Consumer 收不到消息？**
- 检查 Consumer Group 是否注册到 NameServer
- 检查 Topic 是否被自动创建（`autoCreateTopicEnable=true`）
- 用 Dashboard 的「消息查询」看消息是否真的发出

**Q2：消息重复消费？**
- RocketMQ 保证至少一次投递，不保证恰好一次
- **业务幂等**：用唯一 keys（订单号）+ 数据库唯一约束 / Redis SETNX

**Q3：消息堆积严重？**
- 水平扩展 Consumer（增加实例数）
- 检查 Consumer 业务逻辑是否有慢 SQL / 第三方调用
- 启用消费线程池：`consumeThreadMax=64`

**Q4：事务消息回查无限循环？**
- 在 `checkLocalTransaction` 中加超时机制
- 死信队列兜底

## 十二、小结

| 消息类型 | 核心 API | 适用场景 |
|---------|---------|---------|
| 普通 | `syncSend` | 通知、日志 |
| 顺序 | `syncSendOrderly` | 订单状态流转 |
| 延迟 | `syncSend(..., delayLevel)` | 超时取消、提醒 |
| 事务 | `sendMessageInTransaction` | 分布式事务 |
