## 前言

一个用户请求可能经过多个微服务：Gateway → Consumer → Provider → DB。当请求变慢或出错时，如何快速定位是哪个服务的问题？

**Apache SkyWalking** 是一款开源的应用性能监控（APM）工具，专门用于分布式系统的**链路追踪、性能分析和故障定位**。

---

## 1. SkyWalking 是什么？

SkyWalking 提供三大核心能力：

| 能力 | 说明 |
|------|------|
| 🔍 **链路追踪** | 追踪一个请求跨服务的完整调用链 |
| 📊 **性能指标** | 自动统计 QPS、平均响应时间、成功率 |
| 🗺️ **拓扑图** | 可视化展示服务之间的调用关系 |

### 架构

```
┌──────────────────────────────────────┐
│         SkyWalking UI :8080          │
│         (Web 可视化控制台)            │
└──────────────┬───────────────────────┘
               │ HTTP 查询
┌──────────────▼───────────────────────┐
│      SkyWalking OAP :11800/:12800    │
│      (数据收集 + 分析 + 存储)         │
└──────────────┬───────────────────────┘
               │ gRPC (11800)
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌──────┐  ┌──────┐  ┌──────┐
│ Prov │  │ Cons │  │ Gate │
│ider  │  │umer  │  │way   │
│+Agent│  │+Agent│  │+Agent│
└──────┘  └──────┘  └──────┘
```

每个服务启动时通过 **Java Agent（无侵入）**自动向 SkyWalking OAP 上报链路数据。

## 2. Docker Compose 添加 SkyWalking

在 `docker-compose.yml` 中添加：

```yaml
services:
  # ==================== SkyWalking 链路追踪 ====================
  skywalking-oap:
    image: apache/skywalking-oap-server:10.1.0
    container_name: skywalking-oap
    restart: unless-stopped
    environment:
      - JAVA_OPTS=-Xms512m -Xmx512m
      - SW_STORAGE=h2                      # 存储方式（开发用 H2，生产用 ES）
      - SW_CORE_METER_ANALYSIS_ACTIVE_FILES=spring-sleuth,thread-pool
      - SW_TELEMETRY=none
    ports:
      - "11800:11800"   # gRPC：Java Agent 上报链路数据
      - "12800:12800"   # HTTP：SkyWalking UI 查询
    healthcheck:
      test: ["CMD", "bash", "-c", "cat < /dev/null > /dev/tcp/127.0.0.1/11800"]
      interval: 10s
      timeout: 5s
      retries: 5

  skywalking-ui:
    image: apache/skywalking-ui:10.1.0
    container_name: skywalking-ui
    restart: unless-stopped
    depends_on:
      skywalking-oap:
        condition: service_healthy
    environment:
      - SW_OAP_ADDRESS=http://skywalking-oap:12800
    ports:
      - "8080:8080"    # Web 控制台（注意不要与其他服务端口冲突）
```

启动 SkyWalking：

```bash
docker compose up -d skywalking-oap skywalking-ui

# 验证
curl http://localhost:12800

# 浏览器访问 UI
# http://localhost:8080
```

## 3. SkyWalking Java Agent 下载与配置

### 3.1 下载 Agent

从 [SkyWalking 官网](https://skywalking.apache.org/downloads/) 下载 Java Agent，或直接使用项目自带的 `skywalking/agent/` 目录。

Agent 目录结构：

```
skywalking/agent/
├── skywalking-agent.jar       # Agent 入口 JAR
├── config/
│   └── agent.config           # Agent 配置文件
└── plugins/                   # 各种中间件插件
    ├── apm-springmvc-*.jar    # Spring MVC 插件
    ├── apm-feign-*.jar        # Feign 插件
    ├── apm-dubbo-*.jar        # Dubbo 插件
    ├── apm-mysql-*.jar        # MySQL 插件
    └── ...
```

### 3.2 Agent 配置

编辑 `skywalking/agent/config/agent.config`：

```properties
# 服务名（每个服务需不同）
agent.service_name=spring-cloud-alibaba-provider

# OAP 服务地址
collector.backend_service=127.0.0.1:11800

# 日志级别
logging.level=INFO
```

## 4. 微服务集成 Agent

### 4.1 IDEA 中配置 VM Options

在 IDE 的 Run Configuration 中添加 VM Options（每个服务分别配置）：

```
-javaagent:skywalking/agent/skywalking-agent.jar
-Dskywalking.agent.service_name=spring-cloud-alibaba-provider
-Dskywalking.collector.backend_service=127.0.0.1:11800
```

### 4.2 Maven 命令行启动

```bash
# 每个服务启动时加上 -javaagent 参数
mvn spring-boot:run -pl spring-cloud-alibaba-provider \
  -Dspring-boot.run.jvmArguments="-javaagent:skywalking/agent/skywalking-agent.jar -Dskywalking.agent.service_name=spring-cloud-alibaba-provider -Dskywalking.collector.backend_service=127.0.0.1:11800"
```

### 4.3 Docker 部署时的配置

```yaml
# docker-compose.yml 中的 provider 服务
provider:
  build:
    context: .
    dockerfile: spring-cloud-alibaba-provider/Dockerfile
  volumes:
    - ./skywalking/agent:/opt/skywalking/agent:ro
  environment:
    - SW_AGENT_NAME=spring-cloud-alibaba-provider
    - SW_AGENT_COLLECTOR_BACKEND_SERVICES=skywalking-oap:11800
    - JAVA_TOOL_OPTIONS=-javaagent:/opt/skywalking/agent/skywalking-agent.jar
```

## 5. 链路追踪效果

### 5.1 拓扑图

启动所有带 Agent 的服务后，访问 SkyWalking UI（http://localhost:8080），可以在**拓扑图**中看到：

```
User → Gateway → Consumer-Feign → Provider → MySQL
                   │
                   └── Consumer-Ribbon → Provider
```

### 5.2 调用链路

在**追踪**页面可以看到每次请求的完整调用链：

```
HTTP GET /api/user/1 (Gateway)    — 10ms
  ├── Feign /user/1 (Consumer)    — 7ms
  │   ├── HTTP GET /user/1 (Provider) — 5ms
  │   │   └── MySQL SELECT t_user    — 2ms
```

### 5.3 性能指标

- **服务仪表盘**：每个服务的 QPS、平均延迟、成功率
- **端点监控**：每个 API 的响应时间分布（P99/P95/P50）
- **数据库监控**：MySQL 慢查询、连接池状态

## 6. 关键配置

### Agent 服务名

**每个服务必须使用不同的服务名**，否则 SkyWalking 中会混在一起：

| 服务 | Agent 服务名 |
|------|-----------|
| provider | `spring-cloud-alibaba-provider` |
| consumer-feign | `spring-cloud-alibaba-consumer-feign` |
| consumer-ribbon | `spring-cloud-alibaba-consumer-ribbon` |
| gateway | `spring-cloud-gateway` |
| dubbo-provider | `dubbo-provider` |

### 忽略不关心的端点

```properties
# agent.config - 忽略健康检查请求，减少噪音
trace.ignore_path=/actuator/**,/health,/metrics
```

### 采样率

```properties
# 开发环境 100% 采样，生产环境可降低到 10%
agent.sample_n_per_3_secs=-1  # -1 表示全部采样
```

## 7. 支持的中间件（自动埋点）

SkyWalking Agent 通过插件自动为以下组件埋点，**无需修改业务代码**：

| 类别 | 自动支持的组件 |
|------|--------------|
| Web | Spring MVC, WebFlux, Tomcat, Undertow |
| RPC | Feign, Dubbo, gRPC, RestTemplate |
| 数据库 | MySQL, PostgreSQL, MongoDB, Redis(Lettuce) |
| 消息 | Kafka, RocketMQ, RabbitMQ |
| 网关 | Spring Cloud Gateway |
| 定时任务 | @Scheduled |

## 常见问题

### Q: Agent 启动后报 `Connection refused`？

确保 SkyWalking OAP 已启动且端口 11800 可访问：
```bash
docker compose ps skywalking-oap
curl telnet://localhost:11800
```

### Q: UI 中看不到服务？

1. 确认服务的 Agent 配置了正确的 `collector.backend_service`
2. 发送几个请求后等待 1-2 分钟（数据有延迟）
3. 检查 UI 右上角时间范围是否合适

### Q: 生产环境用什么存储？

```yaml
# 开发环境用内嵌 H2
environment:
  - SW_STORAGE=h2

# 生产环境用 Elasticsearch
environment:
  - SW_STORAGE=elasticsearch
  - SW_STORAGE_ES_CLUSTER_NODES=es:9200
```

### Q: 需要给每个服务都配置 Agent 吗？

是的。每个需要追踪的 JVM 服务都需要挂载 Agent。Agent **无侵入**——不需要改代码，只需要加 JVM 启动参数。
