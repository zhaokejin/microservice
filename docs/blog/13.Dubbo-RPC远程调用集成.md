# 13. Dubbo RPC 远程调用集成

> 系列：Spring Cloud Alibaba 2025 微服务实战教程
>
> 前置：完成 [05. Feign 服务消费者](./05.服务消费者-Feign声明式调用.md)

---

## 前言

Spring Cloud 的 Feign 基于 HTTP 协议，适合 RESTful 风格的微服务通信。但如果你的场景需要**高性能、低延迟的 RPC 调用**，**Apache Dubbo** 是更好的选择。

本章展示如何在 Spring Boot 4.x 项目中集成 Dubbo 3.3，使用 Nacos 作为注册中心，实现 RPC 远程调用。

---

## 1. HTTP vs RPC

| 对比维度 | Feign（HTTP） | Dubbo（RPC） |
|---------|-------------|------------|
| 协议 | HTTP/1.1 + JSON | TCP + 自定义协议 |
| 序列化 | JSON | Hessian2 / Protobuf |
| 性能 | 较低（文本协议） | 高（二进制协议） |
| 调试 | 容易（curl/Postman） | 需要专用工具 |
| 跨语言 | ✅ 天然支持 | 有限 |
| 服务治理 | Spring Cloud 体系 | Dubbo 体系 |
| 适用场景 | 对外 API、BFF 层 | 内部服务间高性能调用 |

> **推荐策略**：对外暴露 REST API（Spring Cloud Gateway + Feign），内部服务间用 Dubbo RPC。两者可以在同一个项目中并存。

## 2. 项目结构

```
springboot-dubbo-demo/
├── pom.xml                    # 父 POM（聚合）
├── common-api/                 # 公共 API 模块
│   └── src/main/java/cn/cicoding/dubbo/api/
│       └── SayService.java     # ★ 服务接口定义
├── service-provider/           # 服务提供者
│   └── src/main/java/cn/cicoding/dubbo/provider/
│       ├── ProviderApplication.java
│       └── impl/
│           └── SayServiceImpl.java  # ★ 接口实现
└── service-consumer/           # 服务消费者
    └── src/main/java/cn/cicoding/dubbo/consumer/
        ├── ConsumerApplication.java
        └── controller/
            └── SayController.java   # ★ Dubbo 引用 + REST 暴露
```

**分层设计**：
- `common-api`：定义接口（只有接口，不含实现），provider 和 consumer 都依赖它
- `service-provider`：实现接口 + 暴露 Dubbo 服务
- `service-consumer`：引用 Dubbo 服务 + 对外暴露 REST API

| 子模块 | 端口 | Dubbo 端口 | 角色 |
|--------|------|-----------|------|
| common-api | — | — | 公共接口定义 |
| service-provider | 9005 | 20880 | Dubbo 服务提供者 |
| service-consumer | 8084 | — | Dubbo 服务消费者 + REST API |

## 4. common-api —— 定义接口

### pom.xml

```xml
<dependencies>
    <!-- 无特殊依赖，只定义接口 -->
</dependencies>
```

### SayService.java

```java
package cn.cicoding.dubbo.api;

/**
 * Dubbo 服务接口 —— 定义在 common-api 模块中
 * provider 实现它，consumer 引用它
 */
public interface SayService {
    String sayHelloByName(String name);
}
```

> **为什么需要 common-api？**
> provider 和 consumer 共享同一个接口定义。Dubbo 调用时，consumer 通过接口代理生成 RPC 调用，双方必须使用相同的接口签名和包路径。

## 5. service-provider —— 暴露 Dubbo 服务

### pom.xml 关键依赖

```xml
<dependencies>
    <dependency>
        <groupId>cn.cicoding</groupId>
        <artifactId>common-api</artifactId>
    </dependency>
    <dependency>
        <groupId>org.apache.dubbo</groupId>
        <artifactId>dubbo-spring-boot-starter</artifactId>
    </dependency>
    <dependency>
        <groupId>org.apache.dubbo</groupId>
        <artifactId>dubbo-registry-nacos</artifactId>
    </dependency>
    <dependency>
        <groupId>com.alibaba.cloud</groupId>
        <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
    </dependency>
</dependencies>
```

### application.yml

```yaml
server:
  port: 9005

dubbo:
  application:
    name: dubbo-provider         # Dubbo 应用名
  registry:
    address: nacos://127.0.0.1:8848  # ★ 使用 Nacos 作为注册中心
    username: nacos
    password: nacos
  protocol:
    name: dubbo                  # Dubbo 协议
    port: 20880                  # Dubbo 服务端口
  scan:
    base-packages: cn.cicoding.dubbo.provider  # 扫描 @DubboService

spring:
  application:
    name: dubbo-provider
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848

management:
  endpoints:
    web:
      exposure:
        include: '*'
```

### 启动类

```java
package cn.cicoding.dubbo.provider;

import org.apache.dubbo.config.spring.context.annotation.EnableDubbo;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
@EnableDubbo  // ★ 启用 Dubbo
public class ProviderApplication {

    public static void main(String[] args) {
        SpringApplication.run(ProviderApplication.class, args);
    }
}
```

### 服务实现

```java
package cn.cicoding.dubbo.provider.impl;

import cn.cicoding.dubbo.api.SayService;
import org.apache.dubbo.config.annotation.DubboService;

@DubboService  // ★ 暴露为 Dubbo 服务
public class SayServiceImpl implements SayService {

    @Override
    public String sayHelloByName(String name) {
        return "Hello, " + name;
    }
}
```

> `@DubboService` 是 Dubbo 3.x 的新注解（等价于旧版的 `@Service`，但避免与 Spring 的 `@Service` 冲突）。

## 6. service-consumer —— 引用并调用 Dubbo 服务

### application.yml

```yaml
server:
  port: 8084

dubbo:
  application:
    name: dubbo-consumer
  registry:
    address: nacos://127.0.0.1:8848
    username: nacos
    password: nacos

spring:
  application:
    name: dubbo-consumer
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
```

### 启动类

```java
@SpringBootApplication
@EnableDubbo
public class ConsumerApplication {
    public static void main(String[] args) {
        SpringApplication.run(ConsumerApplication.class, args);
    }
}
```

### Controller —— 最核心的代码

```java
package cn.cicoding.dubbo.consumer.controller;

import cn.cicoding.dubbo.api.SayService;
import org.apache.dubbo.config.annotation.DubboReference;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/demo")
public class SayController {

    @DubboReference  // ★ 注入远程 Dubbo 服务（像本地 Bean 一样使用）
    private SayService sayService;

    @GetMapping("/say/sayHello")
    public ResponseEntity<String> sayHello(@RequestParam("name") String name) {
        // 调用远程服务，完全透明！
        return ResponseEntity.ok(sayService.sayHelloByName(name));
    }
}
```

**`@DubboReference` 的作用**：
1. 从 Nacos 获取 `SayService` 的提供者列表
2. 创建动态代理对象
3. 方法调用时通过 Dubbo 协议发送 RPC 请求
4. 返回结果

## 7. Feign vs Dubbo 对比调用

```java
// Feign 方式（HTTP + JSON）
@FeignClient(name = "service-name")
interface UserFeign {
    @GetMapping("/user/{id}")
    User findById(@PathVariable Long id);
}

// Dubbo 方式（RPC + 二进制协议）
public interface SayService {          // common-api 中定义
    String sayHelloByName(String name);  // 普通 Java 方法，不关注 HTTP
}

@DubboReference  // consumer 中注入
private SayService sayService;
```

| 特性 | Feign | Dubbo |
|------|-------|-------|
| 调用方式 | `userFeign.findById(1L)` | `sayService.sayHelloByName("test")` |
| 底层协议 | HTTP + JSON | TCP + Dubbo 协议 |
| 接口定义 | Feign 接口（需 HTTP 注解） | 普通 Java 接口 |
| 性能 | ~10-50ms | ~1-10ms |

## 9. Dubbo 3.x 关键变化

| 旧 API（2.7.x） | 新 API（3.x） |
|----------------|-------------|
| `@Service` | `@DubboService` |
| `@Reference` | `@DubboReference` |
| `dubbo.registry.protocol` | `dubbo.registry.address` (完整 URL) |
| `dubbo.scan.base-packages` | `dubbo.scan.base-packages` (保持不变) |

## 常见问题

### Q: Dubbo 和 Feign 能同时用吗？

可以。同一个项目中既能暴露 REST API，又能提供 Dubbo RPC 服务。策略建议：
- 对外 API → REST + Gateway
- 内部调用 → Dubbo RPC

### Q: `@DubboReference` 注入为 null？

检查：
1. 启动类是否有 `@EnableDubbo`
2. provider 是否已启动并注册到 Nacos
3. 接口包路径是否一致（common-api 中的包路径）

### Q: Dubbo 端口 20880 冲突？

修改 `dubbo.protocol.port` 为其他端口。
