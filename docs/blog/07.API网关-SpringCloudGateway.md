## 前言

目前我们有 3 个服务在运行：provider（9000）、consumer-feign（8082）、consumer-ribbon（8081）。如果每个服务都直接对外暴露端口，前端需要知道所有服务的地址，这显然是反模式。

**API 网关** 是微服务架构的"大门"，所有外部请求统一经过网关，由网关路由到对应的后端服务。

---

## 1. 网关的作用

```
                        ┌─────────────┐
                        │   Browser    │
                        └──────┬──────┘
                               │ http://localhost:7000/api/user/1
                               ▼
                    ┌──────────────────┐
                    │   Gateway :7000   │
                    │  路由 /api/user/**│
                    │  → StripPrefix=1  │
                    └───┬──────────────┘
                        │ http://provider/user/1
                        ▼
               ┌────────────────┐
               │  Provider :9000 │
               └────────────────┘
```

网关的核心能力：
- **路由转发**：根据路径将请求分发到不同服务
- **负载均衡**：自动从 Nacos 获取实例列表
- **跨域处理**：统一 CORS 配置
- **认证鉴权**：在网关层统一处理
- **限流熔断**：保护后端服务

---

## 2. 模块概览

| 项目 | 值 |
|------|-----|
| 模块名 | `spring-cloud-alibaba-gateway` |
| 端口 | 7000 |
| 服务名 | `spring-cloud-gateway` |
| 技术栈 | Spring Cloud Gateway（WebFlux 响应式） |

> **注意**：Gateway 基于 WebFlux（响应式），与 Spring MVC（Servlet）不兼容。因此 Gateway 模块**不能**引入 `spring-boot-starter-web`。

## 4. 配置 application.yml

```yaml
server:
  port: 7000

spring:
  application:
    name: spring-cloud-gateway
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
        username: nacos
        password: nacos
    gateway:
      discovery:
        locator:
          enabled: true              # 自动根据服务名创建路由
          lower-case-service-id: true # 服务名转小写
      routes:
        # 自定义路由规则
        - id: provider-route
          uri: lb://spring-cloud-alibaba-provider  # lb:// 表示从 Nacos 负载均衡
          predicates:
            - Path=/api/user/**      # 匹配 /api/user/** 的请求
          filters:
            - StripPrefix=1           # 转发前去掉第一段路径 /api

management:
  endpoints:
    web:
      exposure:
        include: '*'
  endpoint:
    health:
      show-details: always
```

### 路由规则详解

| 配置 | 说明 |
|------|------|
| `id: provider-route` | 路由唯一标识 |
| `uri: lb://spring-cloud-alibaba-provider` | `lb://` 前缀启用负载均衡，后面的字符串是 Nacos 服务名 |
| `Path=/api/user/**` | **断言（Predicate）**：匹配此路径的请求才走这个路由 |
| `StripPrefix=1` | **过滤器（Filter）**：去掉第一段路径。`/api/user/1` → `/user/1` |

## 5. 跨域配置

```java
package cn.cicoding.gateway;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.cors.CorsConfiguration;
import org.springframework.web.cors.reactive.CorsWebFilter;
import org.springframework.web.cors.reactive.UrlBasedCorsConfigurationSource;

@Configuration
public class GlobalCorsConfig {

    @Bean
    public CorsWebFilter corsWebFilter() {
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        CorsConfiguration corsConfig = new CorsConfiguration();
        corsConfig.addAllowedHeader("*");        // 允许所有请求头
        corsConfig.addAllowedMethod("*");         // 允许所有请求方法
        corsConfig.addAllowedOriginPattern("*");  // 允许所有来源
        corsConfig.setAllowCredentials(false);    // 是否允许携带 Cookie
        corsConfig.setMaxAge(18000L);             // 预检请求缓存 5 小时
        source.registerCorsConfiguration("/**", corsConfig);
        return new CorsWebFilter(source);
    }
}
```

> **注意**：Gateway 基于 WebFlux，跨域配置用 **`CorsWebFilter`**（reactive），而非 MVC 的 `CorsFilter`。

## 7. 测试验证

### 启动顺序

```bash
# 1. provider 已启动（9000）
# 2. 启动 gateway
mvn spring-boot:run -pl spring-cloud-alibaba-gateway
```

### 通过网关访问

```bash
# 之前直接访问 provider
curl http://localhost:9000/user/1

# 现在通过网关访问（路径加 /api 前缀）
curl http://localhost:7000/api/user/1

# 返回结果相同：
# {"id":1,"userName":"zhangsan","password":"123456","phone":"13800138001"}
```

### 路径变换过程

```
请求:  GET http://localhost:7000/api/user/1

1. Gateway 收到请求
2. 匹配路由规则: Path=/api/user/**
3. StripPrefix=1 去掉 /api
4. 转发: GET http://spring-cloud-alibaba-provider/user/1
5. LoadBalancer 从 Nacos 获取 provider 实例
6. 选择实例: 192.168.1.100:9000
7. 实际请求: GET http://192.168.1.100:9000/user/1
8. 返回结果给客户端
```

## 8. 扩展路由规则

```yaml
spring:
  cloud:
    gateway:
      routes:
        # provider 路由
        - id: provider-route
          uri: lb://spring-cloud-alibaba-provider
          predicates:
            - Path=/api/user/**
          filters:
            - StripPrefix=1

        # consumer-feign 路由
        - id: feign-route
          uri: lb://spring-cloud-alibaba-consumer-feign
          predicates:
            - Path=/api/feign/**
          filters:
            - StripPrefix=1

        # 限流示例
        - id: rate-limit-route
          uri: lb://spring-cloud-alibaba-provider
          predicates:
            - Path=/api/limited/**
          filters:
            - name: RequestRateLimiter
              args:
                redis-rate-limiter.replenishRate: 10   # 每秒允许 10 个请求
                redis-rate-limiter.burstCapacity: 20    # 突发容量
```

## 常见问题

### Q: 网关启动报 `Could not autowire. No beans of 'RestTemplate' type found`？

Gateway 基于 WebFlux，不用 RestTemplate，这是正常的 IDE 警告，不影响运行。

### Q: 访问网关返回 404？

检查：
1. 请求路径是否匹配 `predicates` 中的 Path 模式
2. 目标服务是否在 Nacos 中注册
3. 目标服务是否正常运行

### Q: 引入 `spring-boot-starter-web` 会怎样？

Gateway 和 Spring MVC 冲突，启动报错：
```
Consider renaming one of the beans or enabling overriding
by setting spring.main.allow-bean-definition-overriding=true
```
**解决**：删除 `spring-boot-starter-web` 依赖。
