# 16. Sentinel 熔断限流

> 本教程基于 **Spring Cloud Alibaba 2025.1.0.0 + Spring Boot 4.0.6 + Sentinel 1.8.6**
> 对应代码：sprint 6 阶段 · 第 16 篇
> 难度：⭐⭐⭐ | 预计时间：60 分钟

## 一、为什么需要 Sentinel？

在微服务架构中，一个不稳定的下游服务可能导致整个调用链崩溃（**雪崩效应**）。Sentinel 是阿里巴巴开源的流量防卫兵，提供：

- **流量控制**（QPS / 线程数限流）
- **熔断降级**（慢调用、异常比例、异常数）
- **热点参数限流**（针对特定参数值限流）
- **系统自适应保护**（根据 Load、CPU 使用率自动限流）

## 二、整体架构

本项目在 **三层** 集成 Sentinel：

```
┌─────────────────────────────────────────────────────────┐
│                      Sentinel Dashboard                 │
│                   (可视化规则管理)                        │
└──────────────────────┬──────────────────────────────────┘
                       │ 规则推送
                       ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 1：Gateway 网关层限流（路由维度）                   │
│  → 防止入口流量过大打垮后端                                │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 2：Feign Consumer 调用层熔断（服务维度）            │
│  → 服务不可用时快速失败，返回降级数据                       │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 3：Provider 资源保护（方法 + 热点参数）            │
│  → 单接口限流、热点参数限流                                │
└─────────────────────────────────────────────────────────┘
```

## 五、application.yml 配置

各服务统一添加：

```yaml
spring:
  cloud:
    sentinel:
      transport:
        dashboard: 127.0.0.1:8858   # Sentinel Dashboard 地址
        port: 8721                  # 应用暴露给 Dashboard 的端口
      eager: true                   # 启动时立即连接 Dashboard（便于首次看到应用）
```

> **注意**：`eager: true` 非常重要！默认是懒连接，Dashboard 上看不到应用时排查的第一步就是检查这个配置。

## 六、Provider 资源保护（注解方式）

### 6.1 基础用法

```java
@GetMapping("/{id}")
@SentinelResource(value = "findById", 
                  fallback = "findByIdFallback",
                  blockHandler = "findByIdBlockHandler")
public UserDomain findById(@PathVariable Integer id) {
    return userService.findById(id);
}
```

**fallback vs blockHandler 区别**：

| 维度 | `fallback` | `blockHandler` |
|------|-----------|----------------|
| 触发条件 | 业务异常（RuntimeException 等） | 限流/熔断触发 |
| 异常参数 | `Throwable` | `BlockException` |
| 用途 | 业务兜底 | 限流/熔断兜底 |

### 6.2 降级类实现

```java
public class UserControllerFallback {
    
    public static UserDomain findByIdFallback(Integer id, Throwable e) {
        UserDomain u = new UserDomain();
        u.setId(id);
        u.setUserName("降级数据");
        return u;
    }
    
    public static Map<String, Object> findByIdBlockHandler(Integer id, BlockException e) {
        return Map.of("code", 429, "msg", "用户查询被限流，请稍后重试");
    }
}
```

### 6.3 在 Dashboard 配置规则

启动应用后，Dashboard → 簇点链路 → 找到 `findById` → 流控：

- **阈值类型**：QPS
- **单机阈值**：2（每秒最多 2 次）
- **流控模式**：直接 / 关联 / 链路
- **流控效果**：快速失败 / Warm Up / 排队等待

## 七、Feign 集成（Consumer 端熔断）

### 7.1 启用 Sentinel 支持

```yaml
feign:
  sentinel:
    enabled: true
```

### 7.2 实现 FallbackFactory

**关键点**：用 `FallbackFactory` 而非 `Fallback`，可以拿到异常原因：

```java
@Component
public class UserFeignClientFallbackFactory implements FallbackFactory<UserFeignClient> {
    
    @Override
    public UserFeignClient create(Throwable cause) {
        log.error("Feign 调用 Provider 降级: {}", cause.getMessage(), cause);
        return id -> {
            User fallback = new User();
            fallback.setId(id);
            fallback.setUserName("服务降级 - 暂不可用");
            return fallback;
        };
    }
}
```

### 7.3 在 FeignClient 注解中指定

```java
@FeignClient(value = "spring-cloud-alibaba-provider",
             fallbackFactory = UserFeignClientFallbackFactory.class)
public interface UserFeignClient {
    @GetMapping("/user/{id}")
    User findById(@PathVariable Integer id);
}
```

## 八、Gateway 网关限流

### 8.1 SentinelGatewayConfig 自定义响应

```java
@Configuration
public class SentinelGatewayConfig {
    
    @PostConstruct
    public void initBlockHandlers() {
        BlockRequestHandler blockRequestHandler = (exchange, t) -> {
            Map<String, Object> result = new HashMap<>();
            result.put("code", HttpStatus.TOO_MANY_REQUESTS.value());
            result.put("msg", "请求过于频繁，请稍后再试");
            return ServerResponse.status(HttpStatus.TOO_MANY_REQUESTS)
                    .contentType(MediaType.APPLICATION_JSON)
                    .bodyValue(result);
        };
        GatewayCallbackManager.setBlockHandler(blockRequestHandler);
    }
}
```

### 8.2 Gateway application.yml

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: provider_route
          uri: lb://spring-cloud-alibaba-provider
          predicates:
            - Path=/user/**
```

### 8.3 在 Dashboard 配置网关流控规则

Dashboard → API 网关流控规则 → 新增：

- **资源名**：路由 ID（如 `provider_route`）
- **阈值类型**：QPS
- **单机阈值**：5
- **间隔**：1000ms

## 九、规则持久化到 Nacos（生产必备）

**为什么需要持久化？** 默认规则存在应用内存，应用重启后规则丢失。

### 9.1 添加依赖

```xml
<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-datasource-nacos</artifactId>
</dependency>
```

### 9.2 配置 Nacos 数据源

```yaml
spring:
  cloud:
    sentinel:
      datasource:
        flow-rules:
          nacos:
            server-addr: 127.0.0.1:8848
            dataId: sentinel-flow-rules
            groupId: SENTINEL_GROUP
            rule-type: flow
            data-type: json
```

### 9.3 在 Nacos 创建规则

DataId: `sentinel-flow-rules`，Group: `SENTINEL_GROUP`，格式：

```json
[
  {
    "resource": "findById",
    "limitApp": "default",
    "grade": 1,
    "count": 2,
    "strategy": 0,
    "controlBehavior": 0
  }
]
```

字段说明：
- `grade`：1=QPS, 2=线程数
- `strategy`：0=直接, 1=关联, 2=链路
- `controlBehavior`：0=快速失败, 1=Warm Up, 2=排队等待

## 十一、常见问题

**Q1：Dashboard 看不到应用？**
- 确认 `eager: true`
- 确认服务有访问量（懒加载模式首次访问才会注册）
- 检查 `8721` 端口是否被占用

**Q2：限流规则不生效？**
- 规则名必须与方法名一致
- 资源名不能用 `*` 开头（Sentinel 内部保留）
- 检查 Dashboard 上的「簇点链路」是否有该资源

**Q3：fallback 和 blockHandler 哪个优先？**
- blockHandler 优先（Sentinel 先判定是否限流/熔断，触发后调用 blockHandler）

## 十二、小结

| 层级 | 限流维度 | 适用场景 |
|------|---------|---------|
| Gateway | 路由（粗粒度） | 防入口流量过大 |
| Feign | 服务调用（粗粒度） | 下游服务不可用时快速失败 |
| @SentinelResource | 方法/资源（细粒度） | 保护核心接口、热点参数限流 |
