## 前言

从本章开始，我们正式进入代码编写阶段。首先创建 Maven 多模块父工程，统一管理版本依赖。这是整个微服务项目的骨架，后续所有子模块都将继承自这个父工程。

---

## 1. 版本选型

### 最新稳定版本栈（2025 年推荐）

| 项目 | 版本 | 说明 |
|------|------|------|
| **Spring Boot** | 4.0.6 | Spring Framework 7.0.x 基线 |
| **Spring Cloud** | 2025.1.1 | 对应 Boot 4.0.x 线 |
| **Spring Cloud Alibaba** | 2025.1.0.0 | 对应 Cloud 2025.1.x |
| **JDK** | 17+ | Boot 4.x 最低要求 |

### 版本号命名规则

Spring Cloud 从 2023.x 起使用日历版本号：`YYYY.MINOR.MICRO`
- `MINOR=0` → 对应 Boot 3.x 线（如 2025.0.x）
- `MINOR=1` → 对应 Boot 4.x 线（如 2025.1.x）

Spring Cloud Alibaba 在前者基础上追加第 4 位数字。

> **提示**：SCA 2025.1.0.0 是 Boot 4.x 线下最新版本，移除了 `bootstrap` 配置，改用 `spring.config.import=nacos:...` 加载配置，这是与旧版最大的不同。

## 3. 父 POM 编写

创建项目根目录下的 `pom.xml`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>cn.cicoding</groupId>
    <artifactId>microservice</artifactId>
    <version>1.0.0</version>
    <packaging>pom</packaging>
    <name>microservice</name>
    <description>Spring Cloud Alibaba 微服务示例</description>

    <!-- ========== 版本统一管理 ========== -->
    <properties>
        <java.version>17</java.version>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <spring-boot.version>4.0.6</spring-boot.version>
        <spring-cloud.version>2025.1.1</spring-cloud.version>
        <spring-cloud-alibaba.version>2025.1.0.0</spring-cloud-alibaba.version>
    </properties>

    <!-- ========== 子模块列表 ========== -->
    <modules>
        <module>spring-cloud-alibaba-provider</module>
        <module>spring-cloud-alibaba-provider-file</module>
        <module>spring-cloud-alibaba-consumer-feign</module>
        <module>spring-cloud-alibaba-consumer-feign-file</module>
        <module>spring-cloud-alibaba-consumer-ribbon</module>
        <module>spring-cloud-alibaba-gateway</module>
        <module>spring-cloud-alibaba-nacos-config</module>
        <module>spring-cloud-alibaba-multiple-config</module>
        <module>spring-cloud-alibaba-consul-provider</module>
        <module>spring-boot-admin-server</module>
        <module>springboot-dubbo-demo</module>
    </modules>

    <!-- ========== BOM 依赖管理（不引入实际依赖，只定义版本） ========== -->
    <dependencyManagement>
        <dependencies>
            <!-- Spring Boot BOM -->
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-dependencies</artifactId>
                <version>${spring-boot.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
            <!-- Spring Cloud BOM -->
            <dependency>
                <groupId>org.springframework.cloud</groupId>
                <artifactId>spring-cloud-dependencies</artifactId>
                <version>${spring-cloud.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
            <!-- Spring Cloud Alibaba BOM -->
            <dependency>
                <groupId>com.alibaba.cloud</groupId>
                <artifactId>spring-cloud-alibaba-dependencies</artifactId>
                <version>${spring-cloud-alibaba.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
        </dependencies>
    </dependencyManagement>

    <!-- ========== 构建插件管理 ========== -->
    <build>
        <pluginManagement>
            <plugins>
                <plugin>
                    <groupId>org.springframework.boot</groupId>
                    <artifactId>spring-boot-maven-plugin</artifactId>
                    <version>${spring-boot.version}</version>
                </plugin>
                <plugin>
                    <groupId>org.apache.maven.plugins</groupId>
                    <artifactId>maven-compiler-plugin</artifactId>
                    <version>3.13.0</version>
                    <configuration>
                        <source>17</source>
                        <target>17</target>
                        <parameters>true</parameters>
                    </configuration>
                </plugin>
            </plugins>
        </pluginManagement>
    </build>
</project>
```

### 设计要点

| 要点 | 说明 |
|------|------|
| `packaging=pom` | 父工程本身不产出 JAR，只是聚合管理和版本控制 |
| `dependencyManagement` | 使用 BOM（Bill of Materials）统一管理依赖版本，子模块引入时无需写版本号 |
| `pluginManagement` | 统一管理 Maven 插件版本，配置 `parameters: true` 支持 Java 反射获取参数名 |
| `<modules>` | 声明所有子模块，`mvn compile` 时会按顺序编译所有模块 |

## 5. 验证

```bash
# 编译父工程（子模块还没创建，会跳过不存在的模块）
mvn compile

# 如果 modules 中有未创建的模块，Maven 会警告但不报错
# 后面每创建一个子模块，就在父 POM 中注册对应的 <module>
```

建议此时初始化 Git 仓库并做首次提交：

```bash
git init
git add .
git commit -m "feat(project): 初始化微服务项目父工程"
```

## 关键知识点

### BOM 依赖管理

子模块的 `pom.xml` 只需要这样写，**无需指定版本号**：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <!-- 版本号由父 POM 的 BOM 统一管理 -->
</dependency>
```

### 为什么父 POM 不放 `dependencies`？

父 POM 使用 `dependencyManagement` 而非 `dependencies`：
- `dependencyManagement`：只**声明**版本，子模块需要时自行引入
- `dependencies`：所有子模块**强制继承**，可能引入不需要的依赖
