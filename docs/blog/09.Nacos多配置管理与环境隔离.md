## 前言

上一章我们学会了从 Nacos 加载单个配置文件。实际项目中，配置通常需要拆分——数据库配置、Redis 配置、业务配置各放一个文件。本章学习如何**同时加载多个 Nacos 配置文件**，以及利用 Namespace（命名空间）实现环境隔离。

---

## 1. 为什么需要多配置？

一个典型的微服务需要多种配置：

| 配置类型 | 示例内容 | 变更频率 |
|---------|---------|---------|
| 数据库配置 | URL、用户名、密码 | 低 |
| 业务参数 | 分页大小、超时时间 | 中 |
| 功能开关 | 灰度发布开关、AB 测试 | 高 |

**拆分的好处**：
- 修改业务参数不影响数据库配置
- 可以按不同角色授权不同的配置文件
- 公共配置可以跨服务共享

## 3. 配置 application.yml

```yaml
server:
  port: 9004

spring:
  application:
    name: spring-cloud-alibaba-multiple-config
  config:
    import:
      # ★ 同时导入多个 Nacos 配置文件
      - optional:nacos:cicoding-provider.properties?refresh=true
      - optional:nacos:cicoding-consumer.properties?refresh=true
  cloud:
    nacos:
      config:
        server-addr: 127.0.0.1:8848
        namespace: 3d3be08a-3670-401d-80d0-ac7ddc48115d  # ★ 指定命名空间
        group: DEFAULT_GROUP
        file-extension: properties
        username: ""
        password: ""
      discovery:
        server-addr: 127.0.0.1:8848
        username: ""
        password: ""
  profiles:
    active: dev

management:
  endpoints:
    web:
      exposure:
        include: '*'
  endpoint:
    health:
      show-details: always
```

### 配置要点

```yaml
spring:
  config:
    import:
      # ✅ 可以写多个 import，每个对应一个 Nacos 配置文件
      - optional:nacos:cicoding-provider.properties?refresh=true
      - optional:nacos:cicoding-consumer.properties?refresh=true
```

`optional:` 前缀确保某个配置文件不存在时不会阻止应用启动。

## 5. 代码实现

### 5.1 配置属性类

```java
package cn.cicoding.multiple.config.config;

import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.cloud.context.config.annotation.RefreshScope;
import org.springframework.stereotype.Component;

@Data
@Component
@RefreshScope
@ConfigurationProperties(prefix = "profile")
public class MultiAppConfig {

    /** 来自 cicoding-provider.properties 的 profile.provider */
    private String provider = "default-provider";

    /** 来自 cicoding-consumer.properties 的 profile.consumer */
    private String consumer = "default-consumer";
}
```

### 5.2 Controller — 同时读取两个配置文件

```java
package cn.cicoding.multiple.config.controller;

import cn.cicoding.multiple.config.config.MultiAppConfig;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.cloud.context.config.annotation.RefreshScope;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RefreshScope
public class ConfigMultipleController {

    /** 方式一：@Value 注入（带默认值） */
    @Value("${profile.provider:default-provider}")
    private String cicodingProvider;

    @Value("${profile.consumer:default-consumer}")
    private String cicodingConsumer;

    /** 方式二：@ConfigurationProperties Bean */
    @Autowired
    private MultiAppConfig multiAppConfig;

    @GetMapping("/profile")
    public String hello() {
        return this.cicodingProvider + "<------>" + this.cicodingConsumer;
    }

    @GetMapping("/profile/v2")
    public String helloV2() {
        return multiAppConfig.getProvider() + "<------>" + multiAppConfig.getConsumer();
    }
}
```

## 6. 环境隔离（Namespace）

### 什么是 Namespace？

Namespace 是 Nacos 中最顶层的隔离单元。不同 Namespace 的配置和数据**完全隔离**，互不可见。

```
Nacos
├── Namespace: public（默认）
│   ├── spring-cloud-alibaba-nacos-config.properties
│   └── ...
├── Namespace: dev（开发环境）
│   ├── cicoding-provider.properties
│   └── cicoding-consumer.properties
├── Namespace: test（测试环境）
│   ├── cicoding-provider.properties
│   └── cicoding-consumer.properties
└── Namespace: prod（生产环境）
    ├── cicoding-provider.properties
    └── cicoding-consumer.properties
```

### 创建 Namespace

1. Nacos 控制台 → **命名空间**
2. 新建命名空间：
   - 命名空间名：`dev`
   - 命名空间 ID：自动生成（如 `3d3be08a-3670-401d-80d0-ac7ddc48115d`）
3. 复制生成的 Namespace ID，填入 `spring.cloud.nacos.config.namespace`

### 多环境配置策略

```yaml
# 方案一：多环境配置文件（推荐）
# application-dev.yml
spring:
  cloud:
    nacos:
      config:
        namespace: <dev-namespace-id>

# application-prod.yml
spring:
  cloud:
    nacos:
      config:
        namespace: <prod-namespace-id>

# 方案二：启动参数指定
# java -jar app.jar --spring.cloud.nacos.config.namespace=<id>
```

## 7. 配置层级与优先级

当多种配置来源定义了同一 key 时，优先级从高到低：

```
1. 命令行参数（--xxx=yyy）
2. Nacos 配置中心（spring.config.import）
3. application-{profile}.yml
4. application.yml
5. @ConfigurationProperties 默认值
6. @Value 默认值（:后面）
```

这意味着 **Nacos 中的配置会覆盖本地配置**，这正是我们想要的——配置中心优先。

## 常见问题

### Q: Namespace 和 Group 的区别？

| 维度 | Namespace | Group |
|------|-----------|-------|
| 隔离级别 | 租户级（最强隔离） | 环境/应用级 |
| 典型用途 | 不同团队/不同环境 | 不同应用/不同模块 |
| 跨 Namespace 访问 | ❌ 完全隔离 | ✅ 同 Namespace 内可跨 Group |

### Q: 多个配置文件中有相同的 key 怎么处理？

后加载的覆盖先加载的。`spring.config.import` 中列出的顺序决定加载顺序：
```yaml
import:
  - nacos:config1.properties   # 先加载
  - nacos:config2.properties   # 后加载，相同 key 会覆盖 config1
```
