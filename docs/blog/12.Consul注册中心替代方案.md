> 系列：Spring Cloud Alibaba 2025 微服务实战教程

## 前言

前面所有章节都使用 **Nacos** 作为注册中心。但在某些场景下（跨语言、多数据中心、已有 Consul 基础设施），你可能会选择 **HashiCorp Consul**。本章展示如何用 Consul 作为注册中心，实现与 Nacos 同等的功能。

---

## 1. Nacos vs Consul

| 对比维度 | Nacos | Consul |
|---------|-------|--------|
| 开发者 | 阿里巴巴 | HashiCorp |
| 语言 | Java | Go |
| 一致性协议 | Raft（JRaft） | Raft |
| 健康检查 | TCP/HTTP/MySQL | TCP/HTTP/Script |
| 配置中心 | ✅ 内置 | ✅ 内置（KV Store） |
| 多数据中心 | ✅ | ✅（原生支持） |
| 跨语言支持 | HTTP/gRPC SDK | HTTP/DNS 原生 |
| Spring Cloud 集成 | SCA | Spring Cloud Consul |
| 推荐场景 | Java/Spring 生态 | 多语言/已有 Consul |

> **结论**：如果你是全 Java/Spring 栈，Nacos 是最佳选择。如果需要多语言支持或已有 Consul 基础设施，Consul 是不错的替代方案。

## 2. 启动 Consul

### 2.1 Docker Compose 添加 Consul

在 `docker-compose.yml` 中添加：

```yaml
services:
  # ==================== Consul 注册配置中心 ====================
  consul:
    image: consul:1.15
    container_name: consul-standalone
    restart: unless-stopped
    command: agent -dev -client=0.0.0.0
    ports:
      - "8500:8500"   # HTTP API
      - "8600:8600"   # DNS
    volumes:
      - consul-data:/consul/data
    healthcheck:
      test: ["CMD", "consul", "members"]
      interval: 10s
      timeout: 5s
      retries: 10

volumes:
  consul-data:
```

### 2.2 启动验证

```bash
docker compose up -d consul

# 验证
curl http://localhost:8500/v1/status/leader
# 返回: "127.0.0.1:8300" (表示 Consul 集群 Leader)

# 浏览器访问 UI
# http://localhost:8500
```

## 4. pom.xml — 关键变化

```xml
<dependencies>
    <!-- ★ 使用 Consul Discovery，而非 Nacos Discovery -->
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-starter-consul-discovery</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.mybatis.spring.boot</groupId>
        <artifactId>mybatis-spring-boot-starter</artifactId>
        <version>4.0.1</version>
    </dependency>
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <scope>runtime</scope>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-actuator</artifactId>
    </dependency>
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>
</dependencies>
```

**与 Nacos 模块的区别**：

| Nacos Provider | Consul Provider |
|---------------|-----------------|
| `spring-cloud-starter-alibaba-nacos-discovery` | ❌ 移除 |
| ❌ 不需要 | `spring-cloud-starter-consul-discovery` |

> **注意**：引入 Consul 后**不需要** Nacos 依赖，也**不需要** `spring-cloud-starter-loadbalancer`（Consul Discovery 自带负载均衡）。

## 5. application.yml

```yaml
server:
  port: 9101

spring:
  application:
    name: consul-config-client
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/mytest?...
    username: root
    password: root
  cloud:
    consul:
      host: localhost
      port: 8500
      discovery:
        service-name: consul-config-client   # Consul 中的服务名
      config:
        enabled: true
        format: yaml
        prefix: config
        profile-separator: ':'
        data-key: data

mybatis:
  mapper-locations: classpath:mapper/*.xml
  type-aliases-package: cn.cicoding.model

management:
  endpoints:
    web:
      exposure:
        include: '*'
  endpoint:
    health:
      show-details: always
```

### 配置要点

| 配置 | 说明 |
|------|------|
| `spring.cloud.consul.host/port` | Consul 地址 |
| `spring.cloud.consul.discovery.service-name` | Consul 中注册的服务名 |
| `spring.cloud.consul.config` | Consul KV 配置中心（本章未深入使用） |

## 8. Consul 健康检查

Consul 自动访问 `/actuator/health` 进行健康检查。确保：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: '*'
  endpoint:
    health:
      show-details: always
```

Consul 健康检查端点与 Nacos 不同：
- **Nacos**：通过心跳机制
- **Consul**：定期 HTTP 请求 `/actuator/health`

## 9. 切换注册中心的成本

| 层面 | 改动量 |
|------|--------|
| pom.xml | 更换 1 个依赖 |
| application.yml | 更换配置段 |
| Java 代码 | **0 行**（完全无需改动） |
| Docker | 新增 1 个 Consul 容器 |

这就是 **Spring Cloud 抽象层** 的价值——注册中心可插拔，业务代码零感知。

---

## 常见问题

### Q: Consul vs Nacos 选哪个？

- **只用 Java/Spring**：选 Nacos（集成更深，配置中心更强）
- **多语言团队**：选 Consul（Go Node Python 都原生支持）
- **已有 Consul**：保持现有基础设施

### Q: 可以同时使用 Nacos 和 Consul 吗？

技术上可以，但**不推荐**。双重注册增加复杂度，选一个即可。
