# 08. Nacos 配置中心 —— 动态配置刷新

> 系列：Spring Cloud Alibaba 2025 微服务实战教程
>
> 前置：完成 [07. API 网关](./07.API网关-SpringCloudGateway.md)

---

## 前言

目前所有配置都写在 `application.yml` 里。如果要修改配置（如数据库密码、日志级别），需要改文件→重新打包→重新部署。这在生产环境是不可接受的。

**Nacos 配置中心** 将配置集中管理，支持动态刷新——修改配置后，应用无需重启即可生效。

---

## 1. 配置中心 vs 本地配置

| 对比维度 | 本地 application.yml | Nacos 配置中心 |
|---------|---------------------|---------------|
| 修改方式 | 改文件 + 重新部署 | Nacos 控制台修改即可 |
| 生效时间 | 需要重启应用 | 实时生效 |
| 多环境管理 | 手动切换配置文件 | Namespace 隔离 |
| 版本管理 | Git | Nacos 内置历史版本 |
| 灰度发布 | 不支持 | 支持 |

---

## 2. SCA 2025 的重要变更

### bootstrap 配置已移除

在旧版 Spring Cloud Alibaba 中，需要创建 `bootstrap.yml` 来引导加载 Nacos 配置。SCA 2025.1.0.0 中，这个机制已废弃。

**新版做法**：在 `application.yml` 中使用 `spring.config.import`：

```yaml
# ✅ SCA 2025 推荐方式
spring:
  config:
    import:
      - optional:nacos:spring-cloud-alibaba-nacos-config.properties?refresh=true
```

### Nacos Client 3.x 与 gRPC

SCA 2025 底层使用 Nacos Client 3.x，配置拉取默认通过 gRPC 协议通信。由于 Nacos Server 2.5.x 的 gRPC 配置获取存在兼容性问题，本项目使用 REST API 作为备用方案。

## 5. 配置 application.yml

```yaml
server:
  port: 9003

spring:
  application:
    name: spring-cloud-alibaba-nacos-config
  config:
    import:
      # SCA 2025: 使用 spring.config.import 替代 bootstrap.yml
      # optional: 即使 Nacos 不可达也不阻止启动
      # refresh=true: 配置变更时自动刷新
      - optional:nacos:spring-cloud-alibaba-nacos-config.properties?refresh=true
  cloud:
    nacos:
      config:
        server-addr: 127.0.0.1:8848
        file-extension: properties
        group: DEFAULT_GROUP
      discovery:
        server-addr: 127.0.0.1:8848
        username: ""
        password: ""
  profiles:
    active: dev
```

### 关键配置说明

| 配置 | 说明 |
|------|------|
| `spring.config.import` | 替代 bootstrap.yml，从 Nacos 导入配置 |
| `optional:` 前缀 | Nacos 不可用时应用仍可启动（不会阻塞启动流程） |
| `refresh=true` | 配置修改后自动刷新 `@RefreshScope` 标注的 Bean |
| `file-extension: properties` | 注意：**仅影响旧版 API，不影响 `spring.config.import`** |
| Data ID 必须写完整 | `spring-cloud-alibaba-nacos-config.properties`（含扩展名） |
| `username: ""` | Nacos 开启了 `NACOS_AUTH_ENABLE=false`，必须清空认证信息 |

> ⚠️ **踩坑提示**：如果 Nacos 关闭了认证（`NACOS_AUTH_ENABLE=false`），而 `application.yml` 中又配置了 `username: nacos`，Nacos Config Client 3.x 会主动尝试认证，导致 `login failed: User nacos not found` 错误。

## 6. 代码实现

### 6.1 SPI 注册

在 `src/main/resources/META-INF/spring/` 下创建文件：

`org.springframework.context.ApplicationContextInitializer`：
```
cn.cicoding.nacos.config.loader.NacosRestConfigInitializer
```

### 6.2 REST API 配置加载器

> **背景**：SCA 2025 的 gRPC 配置拉取与 Nacos 2.5.x 存在兼容性问题，配置可能为空。本项目通过 Nacos REST API 作为备用加载方案。

```java
package cn.cicoding.nacos.config.loader;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.context.ApplicationContextInitializer;
import org.springframework.context.ConfigurableApplicationContext;
import org.springframework.core.Ordered;
import org.springframework.core.env.ConfigurableEnvironment;
import org.springframework.core.env.PropertiesPropertySource;

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.net.HttpURLConnection;
import java.net.URI;
import java.nio.charset.StandardCharsets;
import java.util.Properties;

public class NacosRestConfigInitializer
        implements ApplicationContextInitializer<ConfigurableApplicationContext>, Ordered {

    private static final Logger log = LoggerFactory.getLogger(NacosRestConfigInitializer.class);

    @Override
    public int getOrder() {
        return Ordered.HIGHEST_PRECEDENCE;
    }

    @Override
    public void initialize(ConfigurableApplicationContext applicationContext) {
        ConfigurableEnvironment env = applicationContext.getEnvironment();
        String serverAddr = env.getProperty("spring.cloud.nacos.config.server-addr", "127.0.0.1:8848");
        String dataId = env.getProperty("spring.application.name", "application")
                + "." + env.getProperty("spring.cloud.nacos.config.file-extension", "properties");
        String group = env.getProperty("spring.cloud.nacos.config.group", "DEFAULT_GROUP");

        // Nacos v1 REST API：直接返回配置原文
        String url = String.format("http://%s/nacos/v1/cs/configs?dataId=%s&group=%s",
                serverAddr, dataId, group);
        log.info("Fetching Nacos config via REST: {}", url);

        try {
            HttpURLConnection conn = (HttpURLConnection) URI.create(url).toURL().openConnection();
            conn.setConnectTimeout(5000);
            conn.setReadTimeout(5000);
            conn.setRequestMethod("GET");

            if (conn.getResponseCode() == 200) {
                StringBuilder sb = new StringBuilder();
                try (BufferedReader reader = new BufferedReader(
                        new InputStreamReader(conn.getInputStream(), StandardCharsets.UTF_8))) {
                    String line;
                    while ((line = reader.readLine()) != null) sb.append(line).append('\n');
                }
                Properties props = new Properties();
                props.load(new java.io.StringReader(sb.toString()));
                env.getPropertySources().addFirst(
                        new PropertiesPropertySource("nacosRestConfig", props));
                log.info("Loaded {} keys from Nacos: {}", props.size(), props.stringPropertyNames());
            }
            conn.disconnect();
        } catch (Exception e) {
            log.error("Failed to load config from Nacos REST API", e);
        }
    }
}
```

### 6.3 配置属性类

```java
package cn.cicoding.nacos.config.config;

import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.cloud.context.config.annotation.RefreshScope;
import org.springframework.stereotype.Component;

@Data
@Component
@RefreshScope
@ConfigurationProperties
public class AppConfig {
    private String profile = "moren";
}
```

### 6.4 Controller — 两种读取模式

```java
package cn.cicoding.nacos.config.controller;

import cn.cicoding.nacos.config.config.AppConfig;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.cloud.context.config.annotation.RefreshScope;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RefreshScope
public class ConfigClientController {

    /** 方式一：@Value 注入（必须加 @RefreshScope 才能刷新） */
    @Value("${profile:moren}")
    private String profile;

    /** 方式二：@ConfigurationProperties Bean（推荐） */
    @Autowired
    private AppConfig appConfig;

    @GetMapping("/profile")
    public String hello() {
        return this.profile;
    }

    @GetMapping("/profile/v2")
    public String helloV2() {
        return appConfig.getProfile();
    }
}
```

> ⚠️ **重要**：`@Value("${profile:moren}")` 中的 `:moren` 是**默认值**。如果 Nacos 上没有这个配置项，`@Value` 会抛 `PlaceholderResolutionException`，默认值可以防止这个问题。

## 8. 验证动态刷新

```bash
# 启动服务
mvn spring-boot:run -pl spring-cloud-alibaba-nacos-config

# 读取当前配置
curl http://localhost:9003/profile
# 返回: dev111

# 在 Nacos 控制台修改 profile=changed222，点击发布

# 再次读取（无需重启服务！）
curl http://localhost:9003/profile
# 返回: changed222
```

### 刷新原理

```
Nacos 控制台修改配置
        ↓ Nacos 推送变更事件
NacosRestConfigRefresher 监听到变更
        ↓ 重新加载配置到 Spring Environment
Spring Cloud @RefreshScope
        ↓ 销毁并重建标注了 @RefreshScope 的 Bean
应用读取到新值
```

## 9. @Value vs @ConfigurationProperties

| 对比 | @Value | @ConfigurationProperties |
|------|--------|--------------------------|
| 代码量 | 少（单个字段） | 略多（需建配置类） |
| 类型安全 | ❌ 字符串 | ✅ 强类型 |
| 松散绑定 | ❌ | ✅（user-name → userName） |
| 批量读取 | ❌ 逐个注解 | ✅ 一次绑定所有字段 |
| 推荐度 | 1-2 个配置项 | ⭐ Spring Boot 4.x 推荐 |

## 常见问题

### Q: 修改配置后不刷新？

检查：
1. Controller 是否标注了 `@RefreshScope`
2. `spring.config.import` 中是否有 `refresh=true`
3. Data ID 是否写了**完整的文件名**（含 `.properties` 扩展名）

### Q: 启动报 `User nacos not found`？

Nacos 认证关闭时，配置文件中不能有 `username: nacos` / `password: nacos`。改为 `username: ""` / `password: ""` 或直接删除这两行。

### Q: 启动报 `Could not resolve placeholder 'profile'`？

给 `@Value` 加上默认值：`@Value("${profile:默认值}")`。`optional:` 前缀只影响配置导入阶段，不影响 Bean 注入阶段。
